§El problema

Las prácticas de finanzas corporativas son mecánicas: créditos con tablas de amortización de 36 o 60 filas, conversiones de tasas bimestrales, anualidades crecientes. Hacerlas a mano en Excel toma 2-3 horas de trabajo repetitivo — copiar la misma fórmula fila por fila, asegurarse de que cada referencia sea relativa o absoluta correctamente.

El verdadero problema no es la dificultad, sino el volumen y la monotonía. Cada práctica tiene entre 3 y 6 problemas. El procedimiento es siempre el mismo: interpretar el enunciado, escribir los datos, construir la tabla, calcular el resultado.

"Si Claude puede leer una imagen de un problema de finanzas y escribir el código openpyxl correcto, ¿por qué hacerlo yo a mano?"

§Cómo funciona

El script es un pipeline de cinco etapas: captura, envío, generación de código, ejecución y resultado. La clave es que Claude actúa como un compilador de lenguaje natural a openpyxl.

1
Captura con hotkeys
El script registra teclas con la librería keyboard. 1 captura la pantalla completa como pregunta de cálculo, 2 como teoría. Z deshace la última captura. Todo desde background — sin salir del PDF o la pantalla del examen.
2
Codificación base64 + envío
Cada imagen se lee como bytes y se codifica en base64 con base64.standard_b64encode(). El tipo MIME se infiere por extensión. Las imágenes se agrupan en un solo mensaje multimodal a la API de Anthropic.
3
Claude Vision interpreta + genera código
Con un system prompt muy específico, Claude lee los problemas en las imágenes y genera código Python/openpyxl ejecutable. El prompt define un vocabulario de helpers (title(), inp(), frm(), ans()) para consistencia visual entre hojas.
4
Limpieza + ejecución en subproceso
limpiar_codigo() elimina bloques markdown (```) y reconecta strings que la API puede romper en múltiples líneas. El código limpio se escribe en un .py temporal y se ejecuta como subproceso con subprocess.run() — timeout de 3 minutos.
5
Excel profesional generado
El código ejecutado produce un .xlsx con una hoja por problema de cálculo más una hoja de Teoría. El archivo se abre automáticamente con os.startfile() en Windows o subprocess.run(["open", ...]) en macOS.

§El Excel generado

La parte más técnica del proyecto no es la integración con la API, sino el sistema de reglas que guía a Claude para generar un Excel correcto. La restricción clave: ninguna celda puede contener un valor calculado en Python — todo debe ser una fórmula Excel que referencie otras celdas.

"Si el alumno cambia el capital inicial en la celda B3, toda la tabla de amortización se recalcula sola. Eso no es posible si Python hardcodeó los valores."

— Regla crítica del system prompt

Para lograr esto, el system prompt define un vocabulario de funciones helper que Claude debe usar en el código generado. Cada función maneja el formato, el estilo y la lógica de referencia de celdas:

title(ws, r, txt)
Fila de título grande, Calibri 13 bold, borde inferior grueso, merge A:F.
sec(ws, r, txt)
Encabezado de sección en mayúsculas, Calibri 9 bold. Divide visualmente el problema.
inp(ws, r, v)
Dato dado — valor numérico hard-codeado en B. Único lugar permitido para literales.
frm(ws, r, formula)
Paso de procedimiento. Siempre una fórmula Excel (=B3*B4), nunca un número Python.
ans(ws, r, formula)
Resultado final en amarillo (#FFFF00), bold, borde grueso. El resultado que busca el evaluador.
tbl_r(ws, r, vals)
Fila de tabla de amortización. Cada elemento de vals debe ser una fórmula Excel encadenada.
finanzas_gen.py — función ans() openpyxl 
# Celda de resultado — siempre amarilla, siempre fórmula
def ans(ws, r, formula, fmt=M):
    _unmerge_row(ws, r)
    ws.cell(r, 1).border = b_box()
    c = ws.cell(r, 2, _safe_formula(formula))
    c.font      = Font(name="Calibri", size=11, bold=True)
    c.fill      = PatternFill("solid", fgColor=YEL)  # "FFFF00"
    c.alignment = Alignment(horizontal="right", vertical="center")
    c.border    = b_box()
    if fmt: c.number_format = fmt
    ws.row_dimensions[r].height = 20

# Validación de fórmulas antes de escribirlas al Excel
def _safe_formula(f):
    if not isinstance(f, str) or not f.startswith("="):
        return f
    depth, in_str = 0, False
    for ch in f:
        if ch == '"': in_str = not in_str
        elif not in_str:
            if ch == "(": depth += 1
            elif ch == ")": depth -= 1
            if depth < 0: return f"ERROR_FORMULA:{f[:30]}"
    return f if depth == 0 else f"ERROR_FORMULA:{f[:30]}"

_safe_formula() valida que los paréntesis estén balanceados antes de escribir cualquier fórmula al workbook — un guarda-raíles para cuando Claude genera código con strings cortados o paréntesis mal cerrados.

§Qué aprendí

1

El system prompt es el producto. La lógica Python del script tiene unos cientos de líneas. El system prompt que define el vocabulario, las reglas de fórmulas y el estilo del Excel tiene casi el mismo peso. Escribirlo fue la parte más difícil y la que más impacta la calidad del resultado.

2

Generar código para ejecutarlo es un patrón poderoso. En vez de que Claude produzca el Excel directamente (que la API no puede hacer), Claude escribe el código que crea el Excel. Es un nivel de indirección que desbloquea muchas posibilidades para cualquier tool que necesite producir artefactos binarios.

3

La captura con hotkeys es la clave UX. La primera versión requería indicar las rutas de los archivos manualmente. Con keyboard.on_press_key() en background, el flujo se vuelve completamente transparente — seguís en el PDF, presionás 1, y el screenshot ya está guardado.
